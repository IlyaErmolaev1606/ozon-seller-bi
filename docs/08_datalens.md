# 8. Дашборд в Yandex DataLens

Те же витрины, что в `dashboard/index.html`, собранные в DataLens: три вкладки (экономика SKU,
сверки, закупки), селекторы, публичная ссылка. Данные синтетические, поэтому дашборд можно
открывать публично.

**Публичная ссылка:** [datalens.yandex/5cajhqt3ldlco](https://datalens.yandex/5cajhqt3ldlco?_share_link=public) — открывается без входа.

**Где выполнять.** Шаги 1 и 6 и проверку публичной ссылки можно сделать с телефона: у дашбордов
DataLens есть мобильная версия. Шаги 2–5 — с компьютера: конструктор датасетов, чартов и дашборда
построен на перетаскивании полей мышью, а CSV нужно загрузить с диска.

## Как подключены данные и почему так

| Способ | Плюсы | Минусы | Решение |
|---|---|---|---|
| **Файлы (CSV)** | Бесплатно, ничего не нужно разворачивать, 9 файлов в одном подключении | Обновление — заменой файла вручную | **Выбран для демо** |
| Google Sheets | Обновляется автоматически, удобно править руками | Нужно выставить локаль таблицы, лимиты Sheets | Альтернатива, см. в конце |
| PostgreSQL / ClickHouse | Как в проде: витрины пересобираются по расписанию, DataLens читает напрямую | Нужен сервер и учётка | Целевой вариант ([docs/02](02_architecture.md)) |

DataLens бесплатен для одного рабочего места
([тарификация](https://yandex.cloud/ru/docs/datalens/pricing), обновлено 28.09.2026), а публичную
ссылку открывают без входа в DataLens. Чтобы ничего не начали списывать, не приглашайте в свой
DataLens других пользователей и не привязывайте платёжный аккаунт после пробного периода.

## Шаг 0. Подготовить файлы

Готовые CSV лежат в [`datalens/`](../datalens). Пересобрать их из витрин:

```bash
make demo        # демо-данные → витрины DuckDB
make datalens    # витрины → datalens/*.csv
```

| Файл | Витрина | Строк | Для чего |
|---|---|---|---|
| `kpi_month.csv` | `mart_kpi_month` | 4 | Динамика кабинета по месяцам |
| `sku_month.csv` | `mart_sku_month` + ABC/XYZ | 43 | Юнит-экономика SKU × месяц: индикаторы, бары, таблица |
| `pnl_lines.csv` | `mart_sku_month` в длинном формате | 644 | Из чего состоит выручка. Сумма статей = выручке |
| `findings.csv` | `mart_stock_losses`, `mart_supply_acceptance`, `mart_recon_realization`, `mart_oos` | 5 | Где теряются деньги, в рублях |
| `recon_realization.csv` | `mart_recon_realization` | 43 | Отчёт о реализации против API |
| `recon_ads.csv` | `mart_recon_ads` | 4 | Реклама: финансы против Performance API |
| `dq.csv` | `mart_dq` | 7 | Контроль качества данных |
| `purchase_plan.csv` | `mart_purchase_plan` | 11 | Что закупать, где излишки |
| `scenarios.csv` | `mart_scenarios` | 33 | Что будет, если Ozon поменяет правила |

Формат под DataLens: UTF-8, разделитель — запятая, десятичная точка, месяц — текст `ГГГГ-ММ`.
Расходы — положительными числами. Доли (маржа, тариф, ДРР) в файлах нет намеренно: их считает
датасет как отношение сумм, иначе при выборе нескольких SKU получится среднее долей.

## Шаг 1. Включить DataLens (можно с телефона)

1. Войдите в Яндекс ID и откройте [datalens.ru](https://datalens.ru/promo).
2. Нажмите **«Начать в облаке»**, примите условия, нажмите **«Войти»**. Если попросят создать
   организацию — создайте, это бесплатно.
3. Слева откройте **«Коллекции и воркбуки»** → **«Создать»** → **«Воркбук»**, назовите `Ozon Seller BI`.

## Шаг 2. Подключение «Файлы» (компьютер)

1. В воркбуке **«Создать»** → **«Подключение»** → раздел «Файлы и сервисы» → **«Файлы»**.
2. **«Загрузить файлы»** → выберите все 9 CSV из `datalens/`.
3. Для каждого файла проверьте параметры: кодировка `utf-8`, разделитель «Запятая», заголовок
   столбцов включён.
4. Проверьте тип столбца **«Месяц»** — должен быть «Строка». Если DataLens распознал дату, смените
   тип значком слева от названия столбца.
5. **«Создать подключение»** → название `Ozon Seller BI — демо` → **«Создать»**.

Обновить данные позже: в подключении у файла меню → **«Заменить»** → **«Сохранить изменения»**.
Датасеты и чарты подхватят новые цифры сами.

## Шаг 3. Датасеты (компьютер)

Для каждой строки таблицы: на странице подключения **«Создать датасет»** → перетащите таблицу
в рабочую область → вкладка **«Поля»** → настройте агрегацию → **«Сохранить»** с указанным названием.

**Правило агрегации.** Денежные и штучные поля — агрегация **«Сумма»** (без неё DataLens
положит в ось Y «количество уникальных»). Текстовые поля и характеристики (спрос в день, дни запаса,
срок поставки, партия, себестоимость единицы) оставьте без агрегации.

| Датасет | Таблица | Агрегация «Сумма» |
|---|---|---|
| `KPI месяца` | kpi_month | все поля, кроме «Месяц» |
| `Юнит-экономика SKU` | sku_month | от «Продано шт» до «Не использовано баллов» |
| `Структура выручки` | pnl_lines | «Сумма» |
| `Находки` | findings | «Сумма» |
| `Сверка реализации` | recon_realization | все числовые |
| `Сверка рекламы` | recon_ads | все числовые |
| `Контроль качества` | dq | «Сумма» |
| `План закупок` | purchase_plan | остатки, «В заказе у поставщика», «Страховой запас», «Точка заказа», «Заказать шт», «Излишек шт», «Излишек по себестоимости», «Хранение излишка в месяц» |
| `Сценарии` | scenarios | «Изменение прибыли в месяц» |

**Вычисляемые поля.** На вкладке «Поля» — **«Добавить поле»**, имя поля, формула, **«Создать»**.
Доля считается как отношение сумм, поэтому верна и для одного SKU, и для строки «Итого»:

В датасетах `Юнит-экономика SKU` и `KPI месяца`:

| Поле | Формула |
|---|---|
| Маржа | `FDIV_SAFE(SUM([Вклад в прибыль]), SUM([Выручка]))` |
| Фактический тариф Ozon | `FDIV_SAFE(SUM([Удержания Ozon факт]), SUM([Выручка]))` |
| Номинальный тариф Ozon | `FDIV_SAFE(SUM([Удержания Ozon номинал]), SUM([Выручка]))` |
| ДРР | `FDIV_SAFE(SUM([Реклама]), SUM([Выручка]))` |

Только в `Юнит-экономика SKU`:

| Поле | Формула |
|---|---|
| Доля возвратов | `FDIV_SAFE(SUM([Возвраты шт]), SUM([Продано шт]))` |

## Шаг 4. Чарты (компьютер)

Чарт создаётся из датасета: **«Создать чарт»** → тип чарта → поля в секции → **«Сохранить»**.
Тип чарта выбирается в выпадающем списке над секциями X и Y (по умолчанию — «Столбчатая
диаграмма»). У индикатора вместо X и Y одна секция «Показатель».
Номер в названии помогает найти чарт в воркбуке при сборке дашборда.

Форматы полей — значок слева от поля в секции:
* деньги — 0 знаков после запятой, «С разделителем», постфикс ` ₽`;
* доли — формат «Процент», 1 знак после запятой.

## Шаг 5. Дашборд (компьютер)

1. В воркбуке **«Создать»** → **«Дашборд»**. Вкладки: в режиме редактирования шестерёнка вверху
   справа → поле **«Вкладки»** → **«Добавить»**. Нужны три: «Экономика», «Сверки и потери»,
   «Закупки и сценарии».
2. Виджеты перетаскиваются с нижней панели (**«Чарт»**, **«Селектор»**, **«Текст»**,
   **«Заголовок»**). Чарт: перетащите **«Чарт»** на сетку → выберите чарт → **«Добавить»**.
   Каждый чарт — отдельный виджет: «+ Добавить» внутри окна виджета кладёт несколько чартов в один
   блок с переключением вкладками. В поле «Заголовок» номер чарта можно убрать. Заголовки секций —
   отдельные виджеты **«Заголовок»**. Размер блока меняется за правый нижний угол.
3. На вкладке «Экономика» добавьте два селектора (виджет **«Селектор»** → «На основе датасета»,
   датасет `Юнит-экономика SKU`):
   * **Месяц**: поле «Месяц», тип «Список», значение по умолчанию `2026-09`, «Обязательное поле»;
   * **Категория**: поле «Категория», тип «Список», «Множественный выбор», по умолчанию пусто.

   Селекторы и чарты одного датасета связываются сами. Чарты 08 и 09 построены на других
   датасетах, поэтому показывают все месяцы — так и задумано для динамики.
4. Раскладка вкладки «Экономика» сверху вниз:
   * текст-подзаголовок и два селектора;
   * четыре индикатора (01–04) в один ряд;
   * заголовок «Сколько на самом деле зарабатывает каждый артикул», под ним рядом 05 и 06;
   * таблица 07 на всю ширину;
   * заголовок «Динамика», под ним рядом 08 и 09.
5. Для просмотра с телефона задайте порядок виджетов в мобильной версии (настройки дашборда):
   селекторы, индикаторы, затем чарты 05–09.
6. **«Сохранить»** в правом верхнем углу.

Тексты для виджетов:

* Подзаголовок дашборда: «Демо на синтетических данных: витрины собраны пайплайном Seller API →
  DuckDB, код — github.com/IlyaErmolaev1606/ozon-seller-bi. Товары и цифры выдуманы, механики —
  как у кабинета Ozon в 2026 году.»
* Под заголовком «Сколько на самом деле зарабатывает каждый артикул»: «Вклад в прибыль = выручка −
  удержания Ozon после баллов − реклама − себестоимость − брак и утраты − фулфилмент − налоги.
  Номинально удержания Ozon больше выручки: вознаграждение считается от цены продавца. Разницу гасят
  баллы за скидки Ozon.»
* Вкладка «Сверки и потери»: «Сверки — ежедневный процесс: утраты против возмещений, приёмка
  поставок, отчёт о реализации против API, свежесть источников.»
* Вкладка «Закупки и сценарии»: «Закупка — по модели, а не по карточке. Сценарии показывают, сколько
  прибыли в месяц потеряет кабинет при смене правил площадки.»

## Шаг 6. Публичная ссылка (можно с телефона)

1. На дашборде значок меню → **«Поделиться»** → вкладка **«Публично»**.
2. Включите **«Публичный доступ»**.
3. Включите **«Автор дашборда»**: текст `Илья Ермолаев · GitHub`,
   ссылка `https://github.com/IlyaErmolaev1606/ozon-seller-bi`.
4. В «Связанных объектах» оставьте все чарты и датасеты.
5. **«Скопировать ссылку»**. Ссылка из адресной строки браузера не подходит: она требует входа.
6. Откройте ссылку в режиме инкогнито и проверьте все три вкладки.

Публичные данные можно скачать с дашборда, поэтому публиковать можно только синтетику или
обезличенные данные.

## Если что-то не так

* **Индикатор показывает сумму за все месяцы.** Селектор «Месяц» должен быть построен на том же
  датасете, что и чарт (`Юнит-экономика SKU`).
* **Редактор формул ругается на агрегацию.** Проверьте, что поля в формуле числовые. Если ошибка
  остаётся, уберите `SUM()` у полей с агрегацией «Сумма»: `FDIV_SAFE([Вклад в прибыль], [Выручка])`.
* **Числа загрузились как текст.** В подключении смените тип столбца на «Дробное число» и проверьте,
  что выбран разделитель «Запятая».
* **«Месяц» стал датой.** В датасете на вкладке «Поля» смените тип на «Строка».
* **Столбцы чарта 08 выше выручки.** Две меры в Y складываются друг на друга: добавьте Measure Names
  в X после «Месяц» или выберите линейную диаграмму.
* **Доли показаны как 0,19.** Значок поля в секции → «Формат» → «Процент», 1 знак.

## Альтернатива: Google Sheets

1. Создайте таблицу Google, **до импорта** выставьте «Файл» → «Настройки» → «Региональные
   настройки»: «США». С русской локалью числа с точкой превратятся в даты.
2. Импортируйте каждый CSV отдельным листом: «Файл» → «Импорт» → «Вставить новые листы».
3. Откройте доступ «Все, у кого есть ссылка» — «Читатель».
4. В DataLens: подключение **«Google Sheets»** → ссылка на таблицу → включите автообновление.
5. Дальше — те же датасеты, чарты и дашборд.

Плюс: данные обновляются без перезагрузки файлов. Этот путь удобен, если начисления Ozon
выгружаются в Sheets скриптом (Apps Script) по расписанию.

## Что важно в этой сборке

* Данные — витрины из пайплайна Seller API → DuckDB. В проде DataLens подключается к PostgreSQL
  напрямую, витрины пересобираются каждое утро.
* Доли считаются в датасете как отношение сумм, поэтому «Итого» и любые фильтры дают верную маржу.
* Механика баллов: номинально удержания Ozon больше выручки, фактически — 15,8%.
  SKU с отключёнными скидками Ozon платит тариф по номиналу и уходит в минус.
* Вторая вкладка показывает деньги, которые можно вернуть претензиями, третья — закупки по модели
  и стресс-тест правил площадки.
