# 6. Seller API и правила Ozon в 2026 году: что ломает аналитику

Площадка меняет методы и тарифы несколько раз в год. Ниже — изменения, которые напрямую
влияют на пайплайн и юнит-экономику. Даты — по указанным источникам; перед внедрением
каждый пункт сверяется в документации и в кабинете.

## Seller API

| Дата | Изменение | Что делаем в пайплайне |
|---|---|---|
| 06.02.2026 | Отключение устаревших методов складов и остатков FBS (v1 → v2) в марте | Версии методов — в одном месте (`ENDPOINTS`), ответ «obsolete method» — громкая ошибка |
| 13.02.2026 | API-ключи с ограниченным сроком жизни (180 дней), рекомендован OAuth | Дата истечения ключа хранится рядом с ключом, предупреждение за 14 дней |
| 03.09.2026 | По данным OneFill: новые ключи — на 90 дней, бессрочные перестают работать 02.12.2026 | **До 02.12 перевыпустить все ключи интеграций** |
| 06.04.2026 | Блок `Tarification_steps` в методах отправлений; OAuth в Performance API | Тариф по шагам — источник для проверки логистики по заказу |
| 01.04.2026 | Код ТН ВЭД стал обязательным атрибутом для многих категорий | Проверка карточек в справочнике |
| 06.05 → 08.09.2026 | Отключение `/v3/finance/transaction/list` и `/totals`: анонс на 06.07, фактически метод перестал отвечать 08.09 без отдельного уведомления | Финансы — только через `/v1/finance/accrual/by-day` |

### Новые финансовые методы (то, на чём стоит юнит-экономика)

* `/v1/finance/accrual/by-day` — запрос строго за один день, пагинация курсором `last_id`;
  категории начислений `POSTING` / `ITEM` / `NON_ITEM`; услуги лежат на разной глубине
  дерева и описаны только `type_id` (расшифровка — `/v1/finance/accrual/types`).
* `accrual_id` в новом API равен `operation_id` в старом — история сшивается без переписывания.
* `/v1/finance/accrual/postings` **не годится для чистого дохода**: отдаёт только `POSTING`,
  эквайринг (`ITEM`) туда не попадает — сумма по заказу меньше примерно на 1,2%.
* `total_amount` — источник истины: у штрафов и компенсаций детализации может не быть.

Всё это реализовано в `osbi/flatten.py` (рекурсивный обход дерева, остаток до итога — отдельной
строкой) и покрыто тестами `tests/test_flatten.py`.

## Тарифы и правила, влияющие на экономику

| Дата | Изменение |
|---|---|
| 06.04.2026 | Новая сетка вознаграждения (ставки выше 50%) одновременно со снижением логистики |
| июнь–июль 2026 | Отмена наценки за нелокальные продажи (в источнике указаны и 09.06, и 09.07 — дату сверить) |
| 28.08.2026 | Вознаграждение для товаров дороже 300 ₽ — единое для FBO/FBS/realFBS в «Основной категории»; бытовая техника — 51%, электроника — 47% (после снижения на 3 п.п. 24.08) |
| 30.08.2026 | Скидка 3 п.п. за локальную продажу (кроме Москвы и МО, СПб и СЗФО, дальних регионов) |
| 07.09.2026 | Ozon раскрыл фактический средний тариф 1,54% и суммарные расходы 24,73% — разницу закрывают баллы за скидки Ozon |
| 12.09.2026 | Хранение на FBO — с 22-го дня после приёмки |
| 24.09.2026 | Новый расчёт возмещения за утраченный товар: коэффициент зависит от схемы и цены, для залежавшегося товара — меньшая цена |
| 05.10.2026 | Страховка — 0,0838% в день от размера возмещения (рост в 7,3 раза к июлю) |
| 13.10.2026 | Программа страхования от массовых повреждений и атак БПЛА прекращена |
| 01.12.2026 | Штраф 5 ₽ за каждую единицу с неуникальным штрихкодом |

Отдельно: акция «Сбор первых отзывов» может быть подключена площадкой автоматически; плата
за отзыв не возвращается при возврате товара. В витрине — отдельная статья «Платные отзывы»
по SKU и контроль её доли.
