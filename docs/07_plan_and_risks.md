# 7. План внедрения 30/60/90 и подводные камни

## 1–30 дни: единая правда по деньгам

| Неделя | Результат | Как проверяем, что готово |
|---|---|---|
| 1 | Доступы (Seller API, Performance API, кабинет, ФФ), инвентаризация выгрузок и таблиц, интервью с собственником, финдиректором, логистикой: какие 10 решений принимаются еженедельно | Список решений и метрик под них согласован |
| 1–2 | Ежедневная выгрузка начислений, отправлений, остатков, рекламы; маппинг всех `type_id` в статьи P&L | Сумма начислений за закрытый месяц = акт/УПД ± 0,1% |
| 2 | Справочник «модель → карточки → себестоимость партий», налоговый режим согласован | Финдиректор подписывает справочник |
| 3 | Калибровка механики баллов на закрытом месяце: где в API зачёт, как привязан к товару | Фактический тариф по SKU совпадает с «Экономикой магазина» |
| 4 | Дашборд v1 в DataLens: вклад по SKU, удержания, ДРР, сверки, остатки | Собственник и финдиректор открывают его вместо таблиц |

## 31–60 дни: сверки и закупки

* Ежедневные сверки с допусками и алертами; регламент претензий (кто, в какой срок, по какому шаблону).
* Ежемесячная сверка отчёта о реализации и акта сверки (право продавца по закону о платформенной экономике).
* РНП и план-факт по SKU; прогноз и точка заказа по моделям; план поставок по кластерам.
* Метрика качества прогноза (WAPE) по группе A.

## 61–90 дни: решения до денег

* Ценовой калькулятор и оценка акций до входа — с проверкой на истории прошлых акций.
* Экономика новых товаров до закупки (по аналогам), сценарии FBO/FBS, новые площадки.
* Регулярный разбор «топ-10 потерь недели» с собственником.

## Риски и подводные камни

| Риск | Вероятность | Что делаю |
|---|---|---|
| **Механика баллов в API отличается от публичных разборов** | Высокая | Калибровка на закрытом месяце до любых выводов по SKU; два источника: API и «Экономика магазина» |
| **Ozon снова поменяет методы/тарифы без предупреждения** | Высокая | Версии методов в одном месте, мониторинг свежести, «obsolete method» = алерт; тарифы — из начислений, не из таблиц |
| **Ключи API истекают (90 дней; бессрочные — до 02.12.2026)** | Высокая | Дата истечения рядом с ключом, напоминание за 14 дней |
| **Себестоимость неточна** (курс юаня, доставка партии, таможня, брак у поставщика) | Высокая | Себестоимость по партиям, средневзвешенная по остатку; сверка с бухгалтерией |
| **Данные фулфилмента — вручную и с опозданием** | Средняя | Шаблон выгрузки с ФФ, сверка остатков по моделям раз в неделю |
| **Несколько кабинетов/юрлиц** | Средняя | Ключ `seller_account_id` во всех таблицах с первого дня |
| **Дубли карточек одного товара** — каннибализация, штраф за дубли, с 01.12 штраф 5 ₽/шт. за неуникальный штрихкод | Средняя | Справочник модель → карточки, контроль уникальности штрихкодов |
| **Недоверие к цифрам** («в кабинете другое») | Средняя | Каждая цифра раскрывается до отправления; сверка с актом раз в месяц |
| **Таблицы в Google Sheets как система учёта** | Средняя | Sheets — для ввода и справочников, логика — в SQL под версионированием |
| **Продажи в СНГ** (Ozon выкупает товар по своей схеме) | Средняя | Отдельный срез в P&L, своя логика выручки |
| **Безопасность ключей и персональных данных покупателей** | Низкая | Секреты вне кода, минимум прав, ПДн не выгружаются |

## Как понять, что аналитик работает

* Через 30 дней: собственник и финдиректор принимают еженедельные решения по одному дашборду.
* Через 60 дней: каждое расхождение с Ozon имеет владельца и статус; найденные суммы — в отчёте.
* Через 90 дней: закупки и акции согласуются по расчёту до решения, а не после.
